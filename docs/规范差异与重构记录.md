## 结构、命名与依赖决策

- 主课程目录和 artifactId 与 14 份文档一一对应。额外知乎项目和空 MQ 模块归入 `15-cases`，保留源码。
- 保留 `top.cch` 包名。01 文档明确允许替换域名，机械改成作者的 `top.mqxu` 无助于功能且会改变序列化类型名。
- 维持各章独立运行。各章响应风格不同是教学设计，尤其 06 与旧安全接口使用 HTTP 200 + 业务码，不强行抽成一个共享 Result。
- 父 POM 统一 Java 21、Boot 4.1.1、MVC 测试支持和跨模块依赖版本；业务库仍由各模块按需声明。
- 保留现有 HTTP 路径、旧接口响应和默认端口。新增 `spec` Spring profile 使用文档的章节端口；构建目录/坐标迁移在 README 中列出。
- 不覆盖 `docx` 原文。文档中 Spring cron 七字段、表单成功跳转布尔语义等有误之处按框架实测处理，并记录。

## 基线与保护

工作区在本次开始前已有大量 staged/unstaged/untracked 文件，未重置。源码快照及原始 Git 差异保存在本地 `.refactor-backup/`（忽略，不提交）。最终按用户要求以 `refactor` 提交当前项目的完整重构结果，包含这些原有业务源码；不会将原有未提交成果丢弃或单独改写为旧版本。

基线 `mvn test -Dmaven.test.failure.ignore=true` 在原 `10-file` 的 `testCompile` 失败：缺少 `spring-boot-starter-webmvc-test`，后续模块未执行。运行使用本机可用的 Oracle JDK 21；Microsoft JDK 21 的启动崩溃属于本机环境问题。

## 接口、数据与文档兼容

- 目录/核心 artifactId 按章节调整，启动命令和构建引用须使用新目录；默认端口不变。`spec` 仅提供文档端口，不自动迁移客户端配置。
- 原安全系统的 `/api/tasks/**` **仍使用旧 JWT**，不交给课程 JWT 过滤器；两套令牌不能互用。`lesson_user`、`lesson_role` 独立于原 `sec_*` 表。
- 教学中的无锁扣库存演示仍保留竞争窗口；Redisson/SETNX 分支使用条件 SQL 扣减，避免锁租约到期后出现负库存。
- 各模块保持既有响应格式。新字段、接口及可选续传 uploadId 为增量修改；部署 build-info 的 artifactId 按新坐标显示为 `13-deploy`。
- 08 文档的 `top.mqxu`、`mqxu.security` 属于示例命名；项目 Java 包维持 top.cch，新增课程配置前缀按文档保留 mqxu.security。
- Spring cron 实际为六字段；表单 defaultSuccessUrl 的布尔值遵循 Spring 的 saved-request 语义。没有照搬文档中不成立的写法。
- OpenAPI 的 `all.openapi.json` 是 10-doc 中 book/ops 的合并契约，其他独立应用未配置 springdoc，不伪造“全项目 OpenAPI”。
- Prometheus 成功订单指标实际为 `business_orders_created_total`；耗时导出为 summary，告警直接读取 0.95 分位数，不引用不存在的 histogram bucket。

1. **正式环境配置**：是否将默认端口也切为文档端口，需要同步现有客户端；目前采用 spec profile 兼容方案。
2. **真实第三方服务**：OSS Bucket/授权、短信供应商及模板、天气与 SMTP 凭据由使用者提供。此次未发送真实短信/邮件、未写入真实 OSS。08 的短信服务是教学模拟，不应将“生成验证码”视为已投递到手机。
3. **数据库上线迁移**：开发 schema/data 会重建演示表；prod 禁止自动初始化。正式已有数据库的订单 status 字段、课程账户表应采用审核后的迁移脚本，不自动在生产数据库执行。
4. **课后扩展**：文档的分布式调度、多实例持久化、刷新令牌、验证码图形防刷、真实短信网关、生产监控告警投递、Kubernetes/完整持续部署等未作为正文实现直接启用。部分练习要求替换现有实现或故意制造故障，需另定验收目标。原空 MQ 模块无对应规范，保留为扩展占位，不声称已实现消息队列。
5. **工具库状态**：短链、验证码、扫码与分片会话仍采用正文的单实例内存存储；续传可在有效会话中使用 uploadId，不能跨进程重启恢复会话。
6. **Docker**：本机 Docker Desktop 引擎未运行；Compose 配置可解析，但镜像构建、容器就绪探测仅配置在 CI，不能据此宣称本机部署成功。
